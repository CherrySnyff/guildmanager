# План релиза Guild Manager — **1.0.0** (стабильная)

Цель: выпустить первую **production**-версию аддона после серии Alpha-сборок. В репозитории **нет** автотестов PHPUnit; уверенность даёт сочетание **ручной регрессии** (вы) и **технической проверки** (сборка, синтаксис, чистая установка / путь апгрейда).

> **Версионирование XenForo:** в `addon.json` обычно указывают `version_string` вроде **`1.0.0`** и целочисленный **`version_id`**, больший, чем у последней Alpha (например финальный `version_id` после `1000669`). Четвёртый сегмент «1.0.0.0» в продуктовом нейминге часто сводят к **`1.0.0`** в `version_string`; при необходимости оставьте отображаемую строку **`1.0.0 (build N)`** или зафиксируйте внутреннее соглашение проекта.

## 2. Чек-лист для вас (ручная проверка как пользователь/админ)

Проверять на **копии сайта** или на staging; на production — после successful smoke на копии.

### 2.1 ACP (админка XenForo)

- [ ] Установка/обновление аддона без ошибок (**Install** или **Upgrade**).
- [ ] Право **`guildManager`** — доступ к списку гильдий, созданию, логам.
- [ ] Список гильдий открывается, создание новой гильдии (если используете) — без фаталов.
- [ ] Просмотр логов (казна / последователи / репутация и т.д.) — данные на месте после апгрейда.

### 2.2 Публичная карточка гильдии (маршрут `enterum-guilds/{guild_id}`)

- [ ] Вкладки: **Описание, Казна, Склад, Последователи, Репутация, Важные НПС, Участники** открываются; активная вкладка и URL (`tab`, `rep` для репутации) ведут себя ожидаемо.
- [ ] **Уровень организации** и **размер** (Малая / Средняя / …) совпадают с ожиданием по последователям и правилам.
- [ ] **Мировая известность** на вкладке «Репутация» → **кап уровня**: при низкой «Мировой» уровень не выше порога; подсказка **«Уровень не может быть повышен…»** показывается, когда должна.
- [ ] **Направленности**: при незаполненном доступном слоте — **«выберите направленность.»**; сохранение направленностей с нужной ролью и правами (`editGuildDirectionsAny` где применимо).

### 2.3 Права и роли

- [ ] Гость / участник без прав: только просмотр там, где разрешено `view`; нет сохранения чужих форм.
- [ ] **leader / officer / member**: сценарии из `USER_GUIDE_RU.md` (казна, последователи, репутация, склад, описание, смена лидера только у кого положено).
- [ ] Пользователь с **`manageGuildAny`** / точечными `*Any`: админские операции (правка/удаление записей там, где заложено в коде).

### 2.4 Формы и валидация (частые поля)

- [ ] Казна: `https://` для ссылки, сумма ≠ 0, казна не уходит ниже нуля при снятии.
- [ ] Последователи: дата **`дд.мм.гггг`**, ссылка, сумма; итог последователей ≥ 0.
- [ ] Репутация: регион, фракция, сумма; после сохранения пересчитываются агрегаты / уровень (если ожидаете).
- [ ] Описание / участники (BBCode или структурированный блок): сохранение и отображение без «сырого» BBCode там, где должен быть HTML.

### 2.5 Стили и шаблоны

- [ ] После обновления: **Rebuild caches** в XF при необходимости; внешний вид вкладок и таблиц без «сломанной» вёрстки.
- [ ] Тёмная/светлая тема (если используете кастом) — читаемость подсказок уровня и направленностей.

### 2.6 Критерий «можно на production»

- [ ] Нет PHP-ошибок в логах при прохождении сценариев выше.
- [ ] Апгрейд с **последней Alpha** на **1.0.0** на копии БД прошёл успешно; выборочно сравнены 2–3 гильдии (уровень, казна, репутация).

## 3. Что прогнать «с моей стороны» (техника / можно поручить агенту в Cursor)

В репозитории **нет** PHPUnit; ниже — реальный минимум без отдельного тестового стенда или с ним.

| # | Проверка | Как |
|---|----------|-----|
| T.1 | Синтаксис PHP всех файлов аддона | На машине с PHP: `find ... -name '*.php' -exec php -l {} \;` (или аналог в PowerShell); 0 ошибок. |
| T.2 | Анализ статики (опционально) | PHPStan / Psalm при наличии конфига; если нет — пропуск. |
| T.3 | Дифф версии | Убедиться, что **`version_id`** в `addon.json` > предыдущего релиза; шаг апгрейда в `Setup.php` существует. |
| T.4 | Шаблоны | Проверить, что правки в `templates.xml` имеют версии не ниже релиза. |
| T.5 | Чистая установка | Свежий XF 2.2 + установка аддона: таблицы `xf_guild*` создаются, seed правил уровней есть. |
| T.6 | Путь апгрейда | Копия БД с Alpha → Upgrade до 1.0.0: без фатала; при наличии шага пересчёта — выборочно `organization_level` / `influence_cache`. |
| T.7 | CLI (если используете) | `php cmd.php xf-addon:…` / `guild-manager:recalc` на тестовой гильдии — завершение без исключений. |

**Итог для релиза:** отчёт «T.1 пройден, T.3–T.4 согласованы, T.5/T.6 выполнены на staging» + ваш отмеченный чек-лист из §2.

## 4. Go / No-Go перед выкладкой 1.0.0

**Go**, если:

- Ручной чек-лист §2 закрыт на **staging** (или копии БД).
- Техпроверки §3 (минимум **T.1, T.3, T.4** и один из **T.5 / T.6**) зелёные.
- Changelog и резервные копии готовы.

**No-Go**, если:

- Остаются известные регрессии по уровню/репутации/правам.
- Апгрейд с последней Alpha падает или портит данные без миграционного шага.
