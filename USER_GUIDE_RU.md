# Guild Manager — руководство для новичка

Этот документ объясняет, как устроен модуль `Guild Manager` для XenForo:
- какие есть страницы;
- какие поля на этих страницах;
- кто может добавлять/редактировать/удалять данные;
- как работают права пользователя;
- как считаются **уровень организации**, **мировая известность** и **подпись размера**, и какие на вкладке «Описание» показываются **подсказки** (известность / направленности).

## 1. Быстрая модель прав (самое важное)

В модуле одновременно работают **2 уровня прав**:

- Права XenForo-групп (`guild_manager:*`) — глобальные права форума.
- Роль пользователя **внутри конкретной гильдии**: `leader`, `officer`, `member`.

Если у пользователя есть глобальные права `*Any`, он может управлять даже "чужими" гильдиями.  
Если глобальных прав нет, решение принимается по роли в гильдии (матрица ролей).

### Роли в гильдии

- `leader`: полный доступ почти ко всем операциям внутри своей гильдии.
- `officer`: может работать с большинством рабочих блоков (казна/последователи/репутация/склад/участники/описание), но не может менять лидера и **не управляет составом офицеров через панель по ID** (это могут делать только лидер этой гильдии или глобальный админ ниже).
- `member`: только просмотр, без изменений.

**Управление офицерами (роль `officer` в `xf_guild_member`).** В панели **«Редактировать гильдию»** — добавление офицера по **`user_id`**, список текущих офицеров, пакетное снятие роли (обратно в `member`) и замена «офицер A → пользователь B» — доступны **только** если посетитель совпадает с **`leader_user_id`** гильдии **или** имеет глобальное право **`manageGuildAny`**. Обычный офицер по матрице ролей этого UI не получает (`canAppointGuildOfficer`). Технически всё отправляется **POST на один URL** `…/officer`, а тип операции передаётся полем **`gm_officer_op`** (`add` | `remove` | `replace`) — чтобы маршрутизация и ЧПУ не путали сценарии.

## 2. Права XenForo: за что отвечает каждое

Группа прав: `guild_manager`.

- `view` — право просмотра содержимого гильдий (общий permission-флаг модуля).
- `createGuild` — создание гильдий.
- `joinGuild` — вступление в гильдии.
- `maxOwnedGuilds` — числовой лимит гильдий во владении пользователя.
- `manageGuildAny` — админ-уровень: управление любыми гильдиями.
- `editGuildTitleAny` — редактирование названия любой гильдии (зависит от `manageGuildAny`).
- `editGuildDirectionsAny` — редактирование направленностей любой гильдии (зависит от `manageGuildAny`).
- `manageMembersAny` — управление участниками/последователями/транспортом в любых гильдиях.
- `manageTreasuryAny` — управление казной (включая редактирование/удаление записей) в любых гильдиях.
- `manageReputationAny` — управление репутацией (включая редактирование/удаление записей) в любых гильдиях.
- `manageImportantNpcsAny` — управление важными НПС в любых гильдиях.

Отдельно в ACP есть админ-право:
- `guildManager` — доступ к разделам админки модуля (список, создание, логи).

## 3. Страницы модуля

Публичный префикс маршрутов: `enterum-guilds/{guild_id}`.

### 3.1 Вкладка "Описание"

Показывает:
- уровень организации, размер, направленности (при необходимости — **подсказки**: нехватка известности для роста уровня или пустой доступный слот направленности);
- лидера;
- статус "Защита новичка";
- текущий баланс казны;
- BBCode-описание гильдии.

Редактирование:
- **Описание** (`message`) может менять тот, у кого есть право на редактирование описания:
  - лидер своей гильдии;
  - офицер (по матрице ролей);
  - пользователь с `manageGuildAny`.
- **Название гильдии** (`guild_title`) может менять только пользователь с `editGuildTitleAny`.
- **Лидера** (`leader_user_id`) может менять лидер / пользователь с управленческими правами (через `canChangeLeader`).
- **Офицеров** по ID (добавить / массово снять роль / замена в строке списка) — только **лидер этой гильдии** или **`manageGuildAny`** (`GuildWorkflow`: `appointOfficerByUserId`, `removeGuildOfficersByUserIds`, `replaceGuildOfficer` с проверкой `PermissionGuard::assertCanAppointGuildOfficer`). В интерфейсе блок **название + лидер + добавление офицера** вынесены в одну визуальную строку; у каждого офицера блок **«Новый ID» + Заменить** стоит рядом с отображением **#user_id и username** для удобства.
- **Направленности** (`direction_1..direction_4`) зависят от уровня гильдии:
  - слот 1: с уровня 1;
  - слот 2: с уровня 6;
  - слот 3: с уровня 11;
  - слот 4: с уровня 16.

Особое правило по направленностям:
- без `editGuildDirectionsAny` уже зафиксированную направленность менять нельзя;
- можно только заполнить пустой слот;
- повторять одну и ту же направленность в слотах нельзя.

**Подсказка по направленностям.** Сколько направленностей уже **должно** быть указано, определяется уровнем: при уровне **1–5** доступен только слот 1, при **6–10** — слоты 1 и 2, при **11–15** — три слота, с **16** — все четыре (см. список выше). Если **хотя бы один из уже доступных слотов** пуст, на вкладке «Описание» рядом со строкой «Направленности» добавляется текст **«выберите направленность.»** и всплывающая подсказка при наведении на него с тем же смыслом. Это не поле в базе, а **подсказка для игроков**: нужно заполнить пустые слоты в панели редактирования гильдии.

**Уровень организации** в карточке гильдии — это **эффективный уровень**: он не может превысить ни то, что дают последователи по правилам из админки (`xf_guild_level_rule`), ни **потолок по мировой известности**.

**Мировая известность** — числовой показатель из вкладки «Репутация», строка **«Мировая»**, колонка **«Общая»** (тот же расчёт, что использует модуль для капа уровня). От него зависит **максимальный уровень организации**:

| Мировая известность (общая) | Максимальный уровень организации |
|----------------------------:|---------------------------------:|
| меньше 5                    | до 5                             |
| от 5 до 9                   | до 15                            |
| от 10 до 19                 | до 19                            |
| 20 и выше                   | до 20                            |

**Формула в двух словах:** число последователей определяет «сырой» уровень по таблице уровней; мировая известность задаёт верхнюю границу уровня; в карточе сохраняется **минимум** из этих двух величин.

**Подпись размера** («Малая», «Средняя», «Большая», «Легендарная») считается **от эффективного уровня**, а не от отдельного поля в таблице уровней:

| Эффективный уровень | Подпись размера (как показывает интерфейс) |
|--------------------:|------------------------------------------|
| 1–5                 | Малая                                    |
| 6–15                | Средняя                                  |
| 16–19               | Большая                                  |
| 20                  | Легендарная                              |

**Подсказка по известности уровня.** Если уровень упирается в потолок мировой известности (или по последователям уже можно было бы выше, но известность этого не допускает), рядом с размером («Малая» и т.д.) показываются значок предупреждения и текст **«Уровень не может быть повышен: не хватает известности.»** Текст дублируется во всплывающей подсказке у значка (доступность с клавиатуры и экранные дикторы — через `aria-label` у значка).

После изменений в репутации модуль пересчитывает уровень и подпись размера там, где это заложено в коде операций. При **обновлении аддона** в ACP в отдельные версии могут входить шаги **массового пересчёта** всех гильдий — ориентируйтесь на описание версии в `addon.json` / журнале изменений релиза.

### 3.2 Вкладка "Казна"

Таблица операций и форма добавления.

Поля:
- `character_name` (обязательно),
- `source_url` (обязательно, только валидный `https://...`),
- `amount` (обязательно, не 0),
- `reason` (обязательно).

Права:
- Добавление операции (`/treasury/add`): лидер, офицер (по роли), либо `manageTreasuryAny`/`manageGuildAny`.
- Редактирование записи: только `manageTreasuryAny` или `manageGuildAny`.
- Удаление записи: только `manageTreasuryAny` или `manageGuildAny`.

Бизнес-ограничение:
- нельзя увести баланс казны ниже 0.

### 3.3 Вкладка "Склад"

Таблица предметов и форма добавления.

Поля:
- `item_name` (обязательно),
- `item_description`,
- `rarity` (`common|uncommon|rare|unique`),
- `source_url` (необязателен, но если указан — только `https://...`).

Права:
- Добавление: лидер/офицер/админ (право `canManageStorage`).
- Редактирование: **только** `manageGuildAny` (глобальный админ).
- Удаление: **только** `manageGuildAny` (глобальный админ).

### 3.4 Вкладка "Последователи"

Содержит:
- суммарное количество последователей;
- таблицу операций;
- форму добавления;
- блок транспорта.

Поля операции последователей:
- `character_name` (обязательно),
- `source_url` (обязательно, `https://...`),
- `followers_amount` (обязательно, не 0),
- `date` (обязательно в формате `дд.мм.гггг`).

Права (последователи):
- Добавление: лидер/офицер/админ (`manageMembersAny` или `manageGuildAny`).
- Редактирование: только `manageMembersAny` или `manageGuildAny`.
- Удаление: только `manageMembersAny` или `manageGuildAny`.

Бизнес-ограничение:
- итоговое количество последователей не может быть меньше 0.

### 3.5 Блок "Транспорт" (внутри вкладки "Последователи")

Поля:
- `transport_name` (обязательно),
- `transport_status` (`free` или `busy`).

Права:
- Добавление и редактирование: те же, что у операций последователей.
- Удаление: только `manageGuildAny` (глобальный админ).

### 3.6 Вкладка "Репутация"

Содержит:
- свод по биомам;
- вкладки регионов (`aramidis`, `korzus`, `union`);
- группировку по фракциям;
- форму добавления.

Поля:
- `region_key` (`aramidis|korzus|union`),
- `character_name` (обязательно),
- `source_url` (обязательно, `https://...`),
- `reputation_amount` (обязательно, не 0),
- `faction_name` (обязательно).

Права:
- Добавление: лидер/офицер/админ (`manageReputationAny` или `manageGuildAny`).
- Редактирование: только `manageReputationAny` или `manageGuildAny`.
- Удаление: только `manageReputationAny` или `manageGuildAny`.

### 3.7 Вкладка "Важные НПС"

Список карточек НПС с якорями.

Поля:
- `npc_name` (обязательно),
- `message` / `npc_bbcode` (обязательно, BBCode-текст).

Права:
- Добавление/редактирование/удаление:
  - лидер своей гильдии;
  - либо пользователь с `manageImportantNpcsAny`;
  - либо пользователь с `manageGuildAny`.

### 3.8 Вкладка "Участники"

Показывает список участников в структурированном виде.

Форма редактирования:
- `member_user_id[]` / `member_username[]` — пользователь,
- `member_role[]` — текстовая роль в гильдии (до 60 символов, можно пусто).

Права:
- редактирование блока участников: лидер/офицер/админ (`canManageMembersBlock`).
- поиск пользователей для автодополнения (`find-users`) доступен только тем, кто может менять лидера (`canSearchLeaderUsers`).

### 3.9 Достижения (Achievements)

Маршруты и контроллер есть (`/achievements`), но в текущем шаблоне публичной страницы отдельной вкладки в меню нет.  
Если блок будет включен в интерфейс:
- добавление доступно по праву `canManageAchievements`;
- удаление — по праву смены лидера (`canChangeLeader`).

## 4. Кто может что делать (короткая матрица)

- `member`:
  - просмотр страниц;
  - без добавления/редактирования/удаления.
- `officer`:
  - может: описание, казна (добавлять), последователи (добавлять), репутация (добавлять), склад (добавлять), транспорт (добавлять/редактировать), участники, достижения;
  - не может: смена лидера; **назначение и снятие офицеров через панель по `user_id`** (только лидер своей гильдии или `manageGuildAny`); админские "только Any" операции (редактирование/удаление логов, удаление транспорта, редактирование/удаление склада без админ-права).
- `leader`:
  - все права внутри своей гильдии, кроме тех операций, которые принудительно ограничены глобальными `*Any`.
- Пользователь с `manageGuildAny`:
  - полный глобальный контроль, включая админские операции удаления/правки там, где это явно требуется кодом.

## 5. Частые причины ошибок при сохранении

- `no_permission`:
  - нет нужного глобального права или роль в гильдии не позволяет действие.
- "Запись не найдена":
  - передан неверный ID строки/записи.
- Ошибка URL:
  - поле ссылки должно быть валидным и начинаться с `https://`.
- "Сумма/Количество/Репутация должна быть больше 0 или меньше 0":
  - введено `0`.
- "Количество последователей не может быть меньше 0" / "Недостаточно средств в казне":
  - операция приводит общий итог к отрицательному значению.
- Неверный формат даты для последователей:
  - требуется `дд.мм.гггг`.

## 6. Разделы ACP (для админов)

В админке доступны:
- список гильдий;
- создание гильдии;
- логи: казна, последователи, репутация, склад, транспорт, описание.

Доступ к этим разделам дается админ-правом `guildManager`.

## 7. Практическая рекомендация по настройке прав

Минимальная рабочая схема:
- обычные игроки: только `view`;
- лидеры/офицеры гильдий: без глобальных `*Any`, управление через роль в гильдии;
- модераторы проекта: точечно `manageMembersAny` / `manageReputationAny` / `manageTreasuryAny`;
- техадмин: `manageGuildAny` + (при необходимости) `editGuildTitleAny`, `editGuildDirectionsAny`, `manageImportantNpcsAny`.

Так вы разделяете "внутригильдейское управление" и "глобальную модерацию проекта".

### Примечание по версии документа

Фрагменты про офицеров (панель «Редактировать гильдию», один POST `…/officer`, поле `gm_officer_op`, раскладка полей лидера и добавления офицера) соответствуют логике **Guild Manager с версией аддона не ниже `1.0.14`** (`addon.json`; актуально, например, для **1.0.15**); при более старых сборках возможны отличия UX и маршрутов.
